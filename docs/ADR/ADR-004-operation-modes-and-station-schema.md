# ADR-004: Режимы работы и схема станции

**Дата:** 2026-05-28  
**Статус:** Accepted  
**Связанные задачи:** UX-MODES-001, PHASE-13, PHASE-14, MODE-ANALYSIS-001, DWELL-001, MANUAL-002, TX-DB-001

---

## 1. Контекст и проблема

### 1.1. Разнообразие конфигураций станций

Станции операторов могут существенно отличаться по составу оборудования:

| Конфигурация | Антенна(ы) | Приёмник(и) | Поворотка |
|--------------|-----------|-------------|-----------|
| **Минимальная** | 1× QFH (всенаправленная) | 1× RTL-SDR | Нет |
| **Обзорная** | 2× QFH (VHF + UHF) | 2× RTL-SDR | Нет |
| **Слежение** | 1× Yagi (направленная) | 1× AirSpy | Да (rotctld) |
| **Гибридная** | QFH + Yagi на поворотке | RTL-SDR + AirSpy | Частично (только для Yagi) |
| **Расширенная** | QFH VHF + QFH UHF + Yagi | 3× SDR | Да |

Привязывать layout UI к конкретной конфигурации (например, «каскад 1 = QFH, каскад 2 = direction») — жёстко и не масштабируется.

### 1.2. Ранее рассматривался каскадный подход (отклонён)

Двухкаскадная архитектура (ADR-003, обсуждение 2026-05-27) предполагала:
- Каскад 1 — обзор через QFH (широкая полоса)
- Каскад 2 — сопровождение через direction (узкая полоса)

**Проблемы:**
- Если у оператора только поворотка без QFH — Каскад 1 пустой
- Если две QFH на разные диапазоны — не ложится в модель
- Жёсткая связь «тип антенны → UI-зона» усложняет код и ограничивает

## 2. Принятые решения

### 2.1. Три режима работы (взаимоисключающие)

```
mainMode: 'overview' | 'manual' | 'analysis'
```

| Режим | Назначение | Основной сценарий |
|-------|-----------|-------------------|
| **Авто (Обзор)** | Стратегический мониторинг здоровья эфира по КА. Видно сколько данных приходит по каждому передатчику каждого КА в зоне видимости. Минимальное вмешательство оператора. | «Кто молчит уже N циклов? По какому КА не идут данные?» |
| **Ручной** | Тактика + опер. работа. Панорама эфира по передатчикам с индикацией активности + спектр конкретного канала с водопадом и демодулятором. Полный контроль над приёмником, демодулятором, поворотной платформой. | «Что сейчас в эфире по передатчикам ISS? Настроиться на 437.800, декодировать ТМИ.» |
| **Анализ** | Офлайн-разбор записанного сигнала: три уровня (физический / битовый / байтовый), реверс незнакомого формата ТМИ. Подробно — ADR-007, страница `/analysis`. | «Записал незнакомый сигнал — что это за формат?» |

**Доступность:** Авто и Ручной требуют хотя бы одного радиотракта (при `station_type = basic` недоступны). **Анализ доступен всегда, включая `basic`** — работа с готовой записью не требует железа.

**Имитация — не режим.** Имитатор реализован как обычный радиотракт в конфиге станции (`data/config.json`) и выбирается через селектор тракта в любом режиме.

**«Технологический» режим — не существует.** Поглощён Ручным: Ручной и есть технологический.

**Подразумеваемый workflow:** Авто (вижу что молчит по КА) → ручной toggle → Ручной → панорама (нахожу где импульсы по передатчикам) → клик по строке передатчика → «Спектр» настраивается на эту частоту → демодулятор + результат приёма. Если формат незнаком — запись сигнала в Ручном → Анализ.

#### Терминология

**Радиотракт (Radio Path)** — единица оборудования: антенна + приёмник + (опционально) поворотная платформа. Станция содержит 1..N радиотрактов.

**Тип станции** — в JSON-схеме поля нет: тип **вычисляется** методом `StationConfig.StationType()` по составу трактов (пересчёт автоматический при изменении через UI):

| Тип | Условие |
|-----|---------|
| `basic` | Радиотрактов нет — только карта/небо, mode-bar скрыт |
| `observation` | Все тракты без поворотки |
| `tracking` | Все тракты с повороткой |
| `hybrid` | Есть и без, и с повороткой |

#### Файл и загрузка *(синхронизировано с кодом 2026-07-17)*

- Схема станции — секция `station` **единого конфига** `data/config.json` (путь переопределяется env `SCOUT_CONFIG_PATH`); отдельного `station.json` нет.
- Загрузка/создание с дефолтами — `config.Bootstrap()` при старте (`cmd/server/app.go`).
- Валидация: уникальные `id` трактов, корректные диапазоны частот. `radio_paths` **может быть пустым** — это конфигурация `basic`.
- Редактирование — через модалку настроек (`PUT /api/settings`); UI-редактор визуальной схемы — Phase 2+.

#### Go-структуры

Источник правды — код: `internal/config/types.go` (`StationConfig`, `RadioPath`, `AntennaConfig`, `ReceiverConfig`, `RotatorConfig`). Расширенные поля приёмника (`center_freq_hz`, `gain`, `sample_rate_hz`, `ppm`, `bias_tee`, rtl_tcp) — единственное определение в **ADR-006 §3.2**; здесь не дублируются.

### 2.3. Абстракция Receiver + ScanStrategy

```go
// Receiver — интерфейс конкретного SDR-устройства
type Receiver interface {
    Name() string
    Capabilities() Capabilities
    Tune(frequencyHz uint64) error
    StartStream(ctx context.Context, cfg StreamConfig) (<-chan IQFrame, error)
    Stop() error
}

type Capabilities struct {
    MinFreqHz, MaxFreqHz uint64
    MaxBandwidthHz       uint64
    SupportsParallel     bool
}

// ScanStrategy — стратегия сканирования эфира (для Обзора)
type ScanStrategy interface {
    Name() string
    Plan(passes []*Pass, transmitters map[int][]Transmitter) []ScanTask
    Execute(ctx context.Context, recv Receiver, tasks []ScanTask) <-chan DetectionEvent
}
```

Реализации `ScanStrategy`:
- `HopAndDwellStrategy` — для RTL-SDR (узкая полоса, последовательная перестройка). **Используется и в Авто** (накопление истории `tx_cycle`), **и в Ручном** (накопление панорамы, накопление спектра) — реалтайм не критичен, всё с накоплением.
- `ChannelizerStrategy` — для Airspy/HackRF (широкая полоса, параллельная обработка)

Выбор стратегии определяется автоматически по `Receiver.Capabilities().MaxBandwidthHz` (ADR-006 §2.5). Отдельной `SimulatedStrategy` **нет** *(снята 2026-07-17)*: имитатор — обычный `Receiver` с полосой ≤2.4 МГц и попадает в `HopAndDwellStrategy`.

### 2.4. Планирование сканирования: span, dwell


**Первичный источник — план сеансов, не диапазон антенны.** Оператор может не знать рабочий диапазон подключённой антенны, поэтому опираться на `antenna.freq_range_mhz` как на обязательный вход нельзя. Зато всегда известен список пролетающих КА с частотами передатчиков.

**Span (полоса обзора).** Как параметр Span на спектроанализаторе: одна настройка SDR — `center_hz` + ширина. Ширина одного span = полоса приёмника (`MaxBandwidthHz`). Частоты передатчиков КА в окне времени `[now, now + 1h]` покрываются минимальным числом span (жадное покрытие интервалов). Полезными считаются центральные ~80 % полосы: края режет фильтр, в центре DC-спайк; соседние span берутся с перекрытием.

Не путать: **полоса приёмника** — аппаратная ширина; **span** — конкретное размещение этой ширины на оси частот (объект планирования и склейки панорамы).

- Типичная станция (145.8–146.0 и 435–438) — **1–2 span**, полный цикл обзора ~0.1 с.
- Для сравнения: непрерывный sweep по `[144,148] + [430,440]` — 10 span, ~0.4 с.
- Расчёт одного span: FFT-кадр 1024 бина при 2.048 MSPS = 0.5 мс, накопление ×32 = 16 мс, settle PLL и сброс первых сэмплов ~20 мс → **~36 мс**.

**Горизонт 1 час — гистерезис оси.** Набор span пересчитывается при выходе за окно или смене состава активных КА, а не на каждом пролёте: иначе шкала панорамы дёргается.

**Диапазон антенны — опциональное уточнение.** Если задан: частоты вне него помечаются в UI и могут быть отфильтрованы. Если не задан: жёсткое ограничение только `Capabilities.MinFreqHz/MaxFreqHz`.

**Порядок обхода в MVP (Ручной `SWEEP` и Авто).** Span / цели обходятся **последовательно по возрастанию частоты**. Приоритетный планировщик не нужен, пока типичный цикл — 1–2 span.

**Сколько стоим на частоте (dwell)** — от структуры сигнала:

```
dwell_base = k × frame_bits / baud            // k = 2..3 — запас на синхронизацию
dwell      = clamp(dwell_base, dwell_min, dwell_max)
```

`dwell_min = 0.5 с` (ниже накладные на перестройку 20–50 мс съедают КПД), `dwell_max = 15 с`. Пример: AFSK 1200, кадр AX.25 ≈ 256 байт → 2048 / 1200 = 1.7 с, при `k = 2` → 3.4 с. Если `frame_bits`/`baud` неизвестны — 2 с по умолчанию.

**Как часто возвращаемся (revisit)** — от периода маяка: `revisit_target = beacon_period / 2`. Покрывать dwell'ом весь период маяка (30–60 с) бессмысленно; важно не пропустить передачу, а не досидеть до неё. В MVP revisit реализуется просто как следующий полный проход цикла.

**Поправки по факту (MVP):**

- **Ранний выход:** нет энергии выше порога за `probe_time ≈ 0.3 с` — уходим, не досиживая. Молчащие перестают съедать цикл.
- **Продление при успехе:** кадр начал декодироваться — досиживаем до `dwell_max`, не прерывая на границе `dwell`.

**Phase 2+ (не в MVP `DWELL-001`):** приоритет `w = sin(El) × w_hist`, экспоненциальный backoff пустых визитов, `cycle_budget` для Авто при большом числе целей. Имеет смысл, когда span/TX станет много и простой sequential обход перестанет укладываться в удобный цикл.

**Параметры конфига тракта (MVP):** `dwell_min`, `dwell_max`, `k`, `probe_time`, `sweep_gain`.  
**Снято из MVP:** `sweep_interval` (был для `MIXED`), `cycle_budget` (Phase 2+).

## 3. Режим «Авто (Обзор)» — подробное описание

### 3.1. Назначение

Стратегический мониторинг здоровья эфира **по КА**. Минимальное вмешательство оператора. Видно сколько пакетов ТМИ принимается по каждому передатчику каждого КА в зоне видимости — за каждый цикл сканирования. Цель — быстро увидеть «кто молчит» и «куда смотреть».

В этом режиме нет «панорамы радиоэфира» внизу — она перенесена в **Ручной** режим как часть блока «Панорама» (§ 4.3). В Авто внизу — **единая таблица «Передатчики»** (`auto-link.js`), связанная подсветкой с Планом сеансов.

### 3.2. Выбор радиотракта

В app-header — селектор радиотракта (dropdown). По умолчанию — первый тракт из схемы.

**Адаптация UI под тип тракта:**

| Тип тракта | Поведение |
|------------|-----------|
| Без поворотки | Сканирование, детектор, пакетная демодуляция; кнопка «Сопровождать» в плане сеансов **заблокирована** |
| С повороткой | То же + кнопка «Сопровождать» доступна; при нажатии оператор **сам** переходит в Ручной режим (авто-перехода нет) |

### 3.4. Связка `План сеансов ↔ Передатчики`

Два виджета связаны взаимной подсветкой. Список КА **не дублируется** в нижней панели — он остаётся только в Плане сеансов справа (как сейчас).

**План сеансов (правая колонка):**
- Список КА в зоне видимости + тех, чей пролёт в ближайшее время.
- Hover/click по строке КА — становится «выбранным КА» (хайлайт).

**Передатчики (нижняя панель, единая таблица, `auto-link.js`):**
- Список передатчиков **всех КА группы** (КА в зоне видимости + те, чей пролёт в ближайшее время — те же, что в Плане сеансов справа).
- Список **сгруппирован по КА** (заголовки групп = имя КА), порядок групп = порядок в Плане сеансов.
- Колонки строки: частота · модуляция, RSSI-бар, SNR, Lock, «Декод. / Битые», Доплер (`range_rate`), **мини-водопад** (`WaterfallCell` ~140×22 px — индикатор активности, рисуется клиентом по скаляру `power`, см. ADR-002 §I.9), **Результат** (§ 3.7).
- Источник списка — § 8 (SatNOGS + локальная БД + детектированные unknown).

**Модель подсветки:**

| Действие | Что подсвечивается |
|---|---|
| Hover/click по КА в Плане сеансов | Группа этого КА в таблице передатчиков (рамка/фон) |
| Hover по строке передатчика | Строка КА в Плане сеансов |

**Что подсветка НЕ делает:**
- Не настраивает SDR. Авто-tune отсутствует — он несовместим с принципом «Авто = пассивный мониторинг».
- Не переключает режим. Переход в Ручной — только вручную через toggle в app-header.

### 3.5. Источники данных

- **Список КА в Плане сеансов** — `PassService` (как сейчас).
- **Список передатчиков** — объединение передатчиков всех КА из Плана сеансов; для каждого КА список берётся по § 8 (SatNOGS + локальная БД + детектор).
- **Метрики и активность** — единственное SSE-событие **`tx_cycle`** (одно на завершённый цикл сканирования): `power`, `packets`, `snr_db`, `lock`, `history[]`. Формат — ADR-002 §I.9. Источник: mock `TxCycleMock` → live `HopAndDwellStrategy` (SDR-005).

### 3.6. Детектор пакетов

- В MVP: энергетический детектор (мощность в полосе выше threshold + длительность > N мс) — задача `DEMOD-004`.
- Attribution к передатчику: по совпадению частоты с известным каналом (SatNOGS/локальная БД) ± допуск Doppler.
- Энергия вне известных каналов → `unknown`-несущая (см. § 8.3).

### 3.7. Колонка «Результат» — Авто остаётся пассивным

Колонка показывает **тип принятых данных и краткий итог**, но не воспроизводит и не разворачивает их:

| Тип pipeline | Что в колонке |
|--------------|---------------|
| ТМИ | число кадров за цикл + метка последнего (например `47 кадр · 21:14:07`) |
| Голос / CW | тип данных (`FM voice`, `CW`) без плеера |
| SSTV / APT / LRPT | тип данных + пометка «открыть в Ручном» |
| Незнакомый | `unknown` + пометка «записать и разобрать в Анализе» |

**Почему без аудио.** Один приёмник в hop-and-dwell (§ 2.4) непрерывный звук не отдаёт физически — только фрагменты по длительности `dwell`. Прерывистое аудио вводит оператора в заблуждение больше, чем помогает. Аудио, изображения и разворот результата — только в Ручном (§ 4.7), где приёмник стоит на одном канале.

Это сохраняет исходный принцип: **Авто = наблюдение, Ручной = работа.** Переход между ними — только вручную (§ 6.2).

## 4. Режим «Ручной» — подробное описание

### 4.1. Назначение

Тактика + опер. работа. Точная работа с конкретным КА через выбранный радиотракт: панорама эфира по передатчикам с индикацией активности (тактика) + спектр конкретного канала с водопадом и демодулятором (опер.). Полный контроль над приёмником, демодулятором, поворотной платформой. Поглощает ранее обсуждавшийся «Технологический» режим.

### 4.2. Выбор радиотракта

Селектор радиотракта в app-header рядом с toggle режимов. Пользователь явно выбирает, с каким трактом работать.

**Адаптация UI:**

| Тип тракта | Вкладка «Антенна» | Наведение |
|------------|-------------------|-----------|
| **Всенаправленная** (без ротатора) | Только расчётное направление КА (виртуальная цель); колонки «Антенна» и «Расхожд.» — прочерк | Наводить нечем: тумблера режима нет, крестовина заблокирована; пояснения — только во всплывающей подсказке |
| **Направленная** (с ротатором) | Отсчёт «Антенна \| КА \| Расхожд.» + тумблер **Ротатор: Авто \| Ручной** | Авто: антенна ведёт КА, взятый follow-иконкой; Ручной: оператор наводит крестовиной |

### 4.3. Элементы UI — layout

> **Ревизия компоновки (2026-10-07): вкладки по режимам SDR.** Заменяет двухколоночную компоновку 2026-08-14. Радиотракт в MVP — один RTL-SDR, обзор и приём канала взаимоисключающи (§ 4.4). Когда панорама и спектр стояли на одном экране, половина его всегда пустовала, а колонка управления висела и в обзоре, где крутить нечего. Теперь сверху сквозной таймлайн пролётов, под ним три вкладки: «Панорама» и «Спектр» и есть режим SDR, «Антенна» — только вид (с 2026-10-08 «Антенна» тоже `HOLD`, см. ниже). **Структура (сверху вниз):**

| Ярус | Где виден | Состав |
|------|-----------|--------|
| **Таймлайн пролётов** | всегда | Горки угла места по времени на ближайшие часы; общий для всех вкладок |
| **Строка вкладок** | всегда | Только `Панорама \| Спектр \| Антенна` |

**Строки состояния SDR нет (снята 2026-10-08).** Частота и уровень дублировали колонку приёмника, которая теперь видна и на «Антенне»; режим SDR читается по активной вкладке, а на «Антенне» — по компактному спектру. Закреплённая полоска `Az / El / Δ` над вкладками тоже снята: направление антенны читается на вкладке «Антенна».

**Высота — дефицитный ресурс** (100vh без скролла): ярусы задаются `clamp()` от `vh`, остаток высоты забирает главный прибор вкладки — панорама, спектр, индикаторы антенны.

**Кегль приборных значений не уменьшаем.** Частота, уровни и метрики демодуляции читаются оператором с дистанции, поэтому шрифт не режется ради компоновки.

**Автосворачивание правой панели.** Переход в Ручной сворачивает План сеансов и SkyView, переход в Авто разворачивает. Ручной тумблер продолжает работать: оператор может раскрыть панель и в Ручном. Реализация — `applyTrackingModeLayout()` в `app.js`, состояние в `ux.rightCollapsed`.

**Лента передатчиков вместо вертикальной легенды (2026-10-07).** Список «Передатчики» из средней колонки стал одной строкой над содержимым вкладки — как шкала радиоприёмника. Элементы `● имя · частота · модуляция` идут по возрастанию частоты, в том же порядке, что метки на панораме; прокрутка — колесом, стрелками `◀ ▶` и ползунком. Связка с панорамой прежняя: наведение на элемент подсвечивает метку и наоборот, клик по метке прокручивает ленту к передатчику, клик выделяет, двойной клик или Enter настраивает приёмник и берёт КА на сопровождение (§ 4.6). Кнопок в элементах нет (2026-10-08): настроенный передатчик выделен рамкой, повторный двойной клик по нему перестраивает, а не сбрасывает. Ползунок прокрутки виден всегда, чтобы высота ленты не менялась при смене вкладки. На «Спектре» лента — способ сменить канал без возврата в обзор: перестройка внутри `HOLD`. На «Антенне» лента скрыта. Всплывающая инфо-панель над графиком (`.ml-panorama__info`) не возвращается: параметры метки читаются в ленте постоянно.

#### 4.3.1. Вкладки (ревизия 2026-10-07)

Прежняя панель `Эфир | Антенна | Демодулятор` под спектром снята: её содержимое разошлось по вкладкам-режимам.

| Вкладка | Режим SDR | Содержимое |
|---------|-----------|------------|
| **Панорама** | `SWEEP` | FFT панорамы на всю ширину (§ 4.4), под ним водопад обходов, ниже таблица «Эфир». Колонки управления нет: в обзоре оператор только смотрит |
| **Спектр** | `HOLD` | Слева FFT и водопад канала (§ 4.5), под ними результат приёма `Таблица \| Hex \| Диаграмма` (§ 4.7); справа колонка приёмника на всю высоту |
| **Антенна** | не меняет | Сверху `Az \| компактный спектр \| El`, снизу панель наведения во всю ширину; справа та же колонка приёмника |

```
Панорама                                  Спектр
├ Панорама (FFT, вся ширина) ─────────┤   ├ FFT канала ─────────────┬ Приёмник ──────┤
├ Водопад обходов ────────────────────┤   ├ Водопад ────────────────┤ частота · SET   │
├ Эфир: таблица передатчиков ─────────┤   ├ Таблица│Hex│Диаграмма   ┤ настройки       │
                                          │                         │ [Установить]    │
Антенна                                   │                         │ метрики         │
├ Az ──┬ Спектр канала ──────────┬ El ─┬ Приёмник ┤                 │ Данные  ● ■     │
├ Наведение (во всю ширину) ─────────┤ (та же)  ┤                   └─────────────────┘
```

**Вкладка и есть режим SDR.**
- Клик по «Панораме» — `SWEEP`, по «Спектру» — `HOLD` на текущей частоте регулятора. Переключатель «Панорама | Спектр» в колонке тракта и кнопка «Сканирование» в шапке панорамы сняты — их роль играют вкладки.
- Настройка на передатчик (двойной клик по метке, элементу ленты или строке «Эфира») переводит на «Спектр».
- Переход в «Панораму» во время записи IQ — только после подтверждения: тюнер уходит в обзор, запись останавливается.
- «Антенна» — тоже `HOLD` (2026-10-08, раньше вкладка режим не меняла и в `SWEEP` показывала мини-панораму). Смотреть на антенне обзор бессмысленно: проверка наведения — это реакция несущей канала. Частота при входе:
  - со «Спектра» — канал не меняется (с подстройкой регулятором), запись продолжается;
  - с «Панорамы» — передатчик, выделенный одиночным кликом (`ManualPanorama.getSelectedTx`); без выделения — последний канал приёма; если приёма ещё не было — диапазон телеметрии 435–437 МГц (центр 436 МГц, полоса 2 МГц). Настройка на канал сужает полосу до 192 кГц.
  - С «Антенны» на «Панораму» — `SWEEP`, во время записи с тем же подтверждением.
- Вход в Ручной всегда открывает «Панораму» (`SWEEP`, § 4.4). Активная вкладка между сессиями не сохраняется — иначе перезагрузка страницы молча включала бы приём.

**Панорама.** Водопад обходов живёт в другом темпе, чем водопад канала: одна строка — один полный цикл обхода span (секунды), а не кадр FFT. Сбоку шкала времени, чтобы его не принимали за реалтайм. «Эфир» — полная таблица по передатчикам (уровень на обзоре, последний приём, декодировано / битые). Демодуляции в `SWEEP` нет, поэтому столбцы приёма показывают историю прошлых `HOLD`. Лента и «Эфир» дублируют имя и частоту сознательно: лента — навигация по оси панорамы, «Эфир» — разбор.

**Спектр: весь тракт приёма — в колонке справа.** Регуляторы и метрики демодуляции в одной колонке на всю высоту вкладки — настраивать приём и следить за его качеством одно занятие. Порядок: дисплей частоты (регулятор с `SET`, § 4.5) и уровни RF / Audio → секция **Приёмник** (полоса, усиление с АРУ, доплер, сдвиг, полоса канала, squelch, демодулятор) → кнопка «Установить» → метрики (Lock, SNR, Скор., Es/N0, C/N0, BER, RSSI, AFC, Δf, Squelch, FEC, Кадров, Sync, CRC, Посл.) двумя столбцами → секция **Данные** (папка записи, транспорт `● / ■`, имя файла SigMF с меткой времени генерируется при старте). Шапки «Тракт приёма» с именем канала нет (снята 2026-10-08): канал читается по рамке в ленте и по частоте на регуляторе. Отдельные заголовки «Фильтр» и «Демодулятор» сняты: это настройки одного приёмника, а метрики стоят сразу под кнопкой, которая их меняет. Прослушивание — отдельной панелью позже.

**Антенна: компактный спектр между Az и El** — проверка «по свистку»: довернул антенну — видишь реакцию несущей.
- FFT текущего канала без водопада из того же потока `/spectrum` (вкладка «Спектр» в это время не видна, SDR это ничего не стоит). Маркер пика с частотой и уровнем и пунктир ожидаемой частоты: номинал настроенного передатчика со сдвигом Доплера по `range_rate` его КА из SSE (`ManualLayout._expectedFreqMHz`). Несущая на пунктире — коррекция доплера верна, уехала — сдвиг читается сразу. Перестройка регулятором пунктир не двигает. В имитаторе сигнал смещается по своей кривой, поэтому пик и пунктир расходятся — до живого SDR это ожидаемо.
- Снизу во всю ширину — панель наведения (ниже). Секция «Подключение» (адрес rotctld, подключить / отключить, статус, PARK) откладывается до драйвера ротатора (PHASE-8): без бэкенда кнопкам нечего делать. Профиль пролёта на «Антенне» не дублируется — он в виде «Диаграмма» на «Спектре».
- Для всенаправленного тракта — расчётное направление и спектр; наводить нечем (§ 4.2). Крестовина всё равно видна, но заблокирована (2026-10-08): иначе вкладка выглядела недоделанной. Пояснение — `title` при наведении, не текст на экране.
- **Тракт без поворотки: лепесток вместо Az/El (2026-10-08).** Стрелки Az/El для неподвижной антенны ничего не говорят: она никуда не смотрит, вопрос в том, как она слышит КА сейчас. Поэтому квадраты заменены (макет `memory-bank/temp_docs/omni-antenna-icons.html`, вариант Б, `static/js/omni-antenna.js`):
  - на месте Az — каркасный лепесток диаграммы в изометрии над плоскостью земли с N/E/S/W, луч к КА и подпись «КА −N дБ»;
  - на месте El — усиление за пролёт от AOS до LOS, пунктиром угол места, отметка «сейчас». Пролёт — из группы КА в SSE (`aos`, `los`, `sky_path` с бэкенда), тот же, что в таблице наведения;
  - компактный спектр и панель наведения не меняются;
  - на гибридной станции смена тракта в шапке сразу перестраивает вид «Антенны» и панель наведения, без выхода из Ручного.
- **Конструкция антенны — `antenna.kind` в конфиге тракта:** `qfh | yagi | dipole | whip` (квадрифиляр, яги, диполь, штырь). Без поворотки поле обязательно: без него или с неизвестным значением конфиг не валиден и сервер не стартует (`Bootstrap` теперь вызывает `Validate()`). С поворотной платформой поле необязательно. В `/api/config` — `radio_paths[].antenna_kind`. Яги и диполь без поворотки считаются смотрящими в зенит (диполь горизонтальный, полотно по оси N–S), полей наведения нет. Диаграммы упрощённые, без влияния земли: QFH `0.35 + 0.65·sin el`, яги `sin⁷ el`, штырь `cos² el`, диполь `1 − (cos el · cos az)²`; шкала от 0 до −20 дБ, нуль диаграммы ограничен −30 дБ. Задача вида — показать, где антенна слышит хуже, а не точный бюджет линии.
- Квадрат Az/El: `clamp(140px, min(31vh − 56px, (100vw − колонка − 50px) × 0.28), 300px)`. Ограничение по ширине нужно узкому высокому окну: на 1178×1088 без него спектру между квадратами оставалось 236 px.

**Панель наведения (2026-08-14).** Отсчёт по образцу окна ротатора gpredict — [`src/gtk-rot-ctrl.c`](https://github.com/csete/gpredict/blob/master/src/gtk-rot-ctrl.c): строки — оси `AZ` / `EL`, колонки — **Антенна | КА | Расхожд.**, значения выровнены в столбцы; расхождение сверх порога 2° краснеет. Третья строка таблицы — **Пролёт**: время `AOS`, `LOS` (HH:MM) и остаток (`осталось`, либо `до AOS`, если пролёт не начался), отделена сверху линией. Отдельной строки-состояния нет — вердикт «мимо» несёт красный цвет в колонке «Расхожд.». Справа блок ручного наведения — состав описан ниже, в «Ручное наведение».

**Режим ротатора Авто | Ручной (ревизия 2026-08-14).** Тумблер вверху панели наведения, только для направленного тракта (`has_rotator`); для всенаправленного скрыт. **Авто:** антенна ведёт КА, взятый follow-иконкой в списке передатчиков (§ 4.6); ручное наведение (крестовина, поля, шаг) заблокировано (подсказка `title`, не текст на экране); в списке видны follow-иконки. **Ручной:** оператор наводит крестовиной; follow-иконок нет; уход из «Авто» снимает сопровождение. Сопровождение хранит `StateManager` (`getTrackingSatelliteId`), который панель читает; follow-иконка ведёт его клиентски (UI впереди бэкенда, PHASE-8) и `POST /api/tracking/current` — для реального ротатора. Режим — в `ux.rotMode`. Прежние тумблеры внутри панели («Ручной | Авто» как источник tracking, «Связь», «Слежение», `PARK`) сняты — они дублировали источник правды или управляли отсутствующим железом.

**Ручное наведение (ревизия 2026-08-14).** Панель шириной 300 px (250 px на ноутбуке); с ревизии 2026-10-07 — в секции «Наведение» внизу вкладки «Антенна». Сверху поля цели `AZ` / `EL` — они показывают заданное положение и обновляются стрелками крестовины; в центре крестовины кнопка **SET** наводит антенну на введённые в поля значения (Enter в поле — то же). Ниже лента шага крестовины (`0.1/1/5/10°`) — отдельными кнопками с зазором, без встык-сегментов и без подписи; выбранный шаг хранится в `ux.rotStep`. Прежняя «На КА» (снап на спутник) убрана: цель задаётся полями и стрелками.

**Заданное положение — одно состояние** (`_rotTargetAz/_rotTargetEl`): меняется крестовиной и SET, всегда отражается в полях `AZ`/`EL`. `_seedTargetFromAntenna()` подтягивает его из индикаторов при старте и при снятии сопровождения — иначе следующая команда дёрнула бы антенну в устаревшую точку. Пока идёт сопровождение поля показывают положение КА и заблокированы вместе с крестовиной.

**Чего в панели сознательно нет.** Шапки с именем КА — имя есть в плане сеансов и в Map HUD, колонка «КА» подписана источником. Спинбоксов — поля цели обычные текстовые (валидация диапазона, подсветка ошибки), шаг задаётся кнопками.

**Подвкладки `Пролёт / Карта` сняты (2026-08-14).** Заглушка «Мини-карта» удалена — карта уже есть в Авто; когда понадобится мини-карта в Ручном, она вернётся отдельным видом. **Профиль пролёта (ревизия 2026-10-08)** — только в виде результата «Диаграмма» на «Спектре», справа от глазковой диаграммы: оба графика нужны при разборе приёма, а отдельный вид прятал один из них. На «Антенне» угол места КА читается по индикатору El и таблице наведения. Узкой колонки, где профилю оставалось 60 px, больше нет.

Состояние подключения и строка железа стоят рядом в верхней строке панели: «куда подключены» и «подключены ли» — одна мысль, разносить их по разным краям блока незачем. Блок текущих параметров содержит только числа.

**Таблица наведения вместо подписей под графиками (2026-08-14).** Значения «антенна / КА» больше не выводятся под канвасами Az и El — они собраны в одну таблицу в панели ротатора: строки — оси (Азимут, Угол места), колонки — **Антенна | КА | Δ**. Числа стоят друг под другом, поэтому расхождение видно без вычитания в голове, а графики отдают освободившуюся высоту квадратам индикаторов (на 1366×768 — 154 → 182 px). Δ считается в `ManualLayout._updateAntDelta()`: по азимуту — кратчайшая дуга (359° и 1° расходятся на 2°, не на 358°), сверх допуска `POINTING_TOLERANCE_DEG = 2°` значение подсвечивается `--accent-danger`. ### 4.4. Блок 1 «Панорама эфира»

Панорама занимает ярус целиком: FFT по всей ширине колонки РТН. Список «Передатчики» вынесен в среднюю колонку layout'а (§ 4.3) — он общий для панорамы и таймлайна, а не вложен в панораму. Накопление, не реалтайм; источник данных — span из плана сеансов (§ 2.4).

**Метки передатчиков — треугольник, не табличка (2026-08-14).** Постоянные подписи в рамках занимали 48 px сверху при высоте панели 92–144 px, то есть больше, чем сам график сигнала. Теперь над графиком рисуется цветной треугольник на частоте передатчика (одного размера для всех) плюс пунктирная вертикаль, а подпись `имя · частота` выводится только для выбранной или подсвеченной метки. Верхнее поле — 24 px независимо от числа передатчиков, геометрия не прыгает при наведении. Имена и частоты всех передатчиков читаются в ленте передатчиков (§ 4.3). Попадание по метке считается по горизонтальной близости к её вертикали (±7 px на всей высоте графика) — целиться в треугольник не нужно.

**FFT spectrum (склейка span):**
- Ось строится из **span вокруг частот КА** в окне `[now, now + 1h]`, а не из непрерывного диапазона антенны. Типично 1–2 span (например `145.0–146.6 ≈ 436.0–438.0`) — на оси нет участков, где заведомо нечего слушать.
- Несколько span на одной горизонтальной оси через разделитель `≈` (как в референсе `docs/img/overview-panorama.png`).
- **Два разных накопления, не путать:** внутри пикселя по частоте — всегда `max`; по времени — выбор оператора `avg×N` (по умолчанию) или `max-hold`.
- Шкала dB слева (0..−100 dBFS).
- **Возраст данных.** В `SWEEP` ось обновляется одним проходом: за радарной линией — свежие данные текущего цикла, перед ней — предыдущий проход (приглушён). В `HOLD` панорама заморожена; в шапке — возраст (`от 23:14:07`).

**Политики обновления панорамы:**

Панорама и мгновенный спектр **взаимоисключающие** — SDR в единицу времени либо сканирует span, либо стоит на одном канале. Политика `MIXED` (time-sharing приёма с редкими вставками обзора) **снята**: для RTL-SDR она рвала демодулятор и усложняла планировщик без выигрыша в UX.

| Политика | Когда | Поведение |
|----------|-------|-----------|
| `SWEEP` | вход в Ручной; вкладка «Панорама» | непрерывные циклы обзора span по возрастанию частоты; Спектр/демод неактивны |
| `HOLD` | вкладка «Спектр»; настройка на передатчик / ручная настройка частоты; запись → Анализ | обзор выключен, панорама замерла (данные сохранены), Спектр + демодулятор активны |

**Переходы:**

```
вход в Ручной ──► SWEEP
SWEEP ──(вкладка «Спектр» / настройка на TX / tune)──► HOLD
HOLD  ──(вкладка «Панорама»; при записи — с подтверждением)──► SWEEP
```

Возобновление `SWEEP` продолжает с последнего span (или с начала — по кнопке с modifier/опцией «сначала»). Автопереходов «по таймеру» нет.

**Визуализация `SWEEP` — радарная линия:**
- Вертикальная черта движется слева направо по оси частот.
- За линией — свежие данные текущего прохода; перед линией — данные предыдущего прохода (приглушённые).
- При переходе через `≈` линия перескакивает на начало следующего диапазона.
- В шапке панорамы: `Сканирование: цикл N, 145.8 MHz` (номер цикла + текущая частота).

**«Широкий обзор»** по `antenna.freq_range_mhz` (поиск незнакомых несущих вне частот плана) — отдельная опция по кнопке в шапке панорамы, без расписания; доступна, когда диапазон антенны задан. Работает только в `SWEEP`.

**Подвох усиления.** На время `SWEEP` усиление фиксируется (`sweep_gain`, отдельный от усиления приёма параметр): AGC даёт разные уровни на соседних span и ломает стыки склейки. В `HOLD` действует усиление приёма.

**Чипы-маркеры (на FFT):**
- Над каждой известной несущей — треугольник `▼` + цветной чип со статусом передатчика:
  - ● зелёный — ТМИ декодируется
  - ● жёлтый — импульсы без декода
  - ● фиолетовый — кодированный/шифр
  - ○ серый — передатчик молчит (нет сигнала за окно)
- Источник списка несущих — § 8 (SatNOGS + локальная БД + детектированные unknown).
- Hover по чипу — tooltip с полным описанием передатчика.

**Шкала частот** — горизонтальная, общая для FFT и чипов; разделитель `≈` между диапазонами.

**Список передатчиков** (исходная спецификация строки; с ревизии 2026-10-07 это лента над вкладкой, § 4.3, где оба этажа сведены в одну строку):

Заголовок панели: «Передатчики». Каждая строка — **2 этажа**:

| Этаж | Содержимое |
|------|------------|
| 1 | ●/○ (тот же цвет, что у чипа на FFT) + **имя** передатчика (`ISS-VOICE`, `ISS-FSK (AFSK 1200)`) |
| 2 | **`частота · модуляция`** — monospace, приглушённый текст (`145.825 · FM`, `437.800 · FSK 1k2`) |

**Намеренно убрано** из основного вида (в отличие от Авто-режима `auto-link.js`): bar-chart активности, счётчики пакетов, широкая таблица с колонками. Статус «есть сигнал / молчит» — только через цвет ● и чип на FFT.

Молчащие: ○ + dim + `— молчит` на 2-м этаже. Tooltip (hover): NORAD, baud, SNR, пакеты за окно, источник (SatNOGS / локальная БД / detected unknown).

**Связь список ↔ FFT:** hover по строке → подсветка чипа и полосы на FFT; hover по чипу → подсветка строки. Клик → § 4.6.

**Follow-иконка ◎** — слева от имени, видна только когда ротатор в «Авто». Toggle: клик — взять КА передатчика на сопровождение (приёмник + ротатор), повторный клик — снять (§ 4.6). Ведомый передатчик подсвечен. Список строится по КА текущей группы пролётов (передатчик закреплён за КА); частота и модуляция — из БД передатчиков (TX-DB-001), до неё — шаблонные mock-значения.

**Сортировка по умолчанию:** по частоте (совпадает с осью FFT); внутри диапазона — активные сверху, молчащие снизу.

**Достоверность статуса «молчит».** Разрешение панорамы — ~2 кГц на бин (2.048 MSPS / 1024). Узкополосный CW-маяк шириной ~50 Гц теряет в таком бине порядка 16 дБ отношения сигнал/шум и может не проявиться вовсе. Для узкополосных передатчиков ○ на панораме означает «не видно на обзоре», а достоверный вывод даёт только результат dwell (§ 2.4).

### 4.5. Блок 2 «Спектр: FFT + водопад»

Опер. инструмент: точечная настройка на один канал с накоплением мгновенного FFT и водопада в полосе SDR (≤ ~2.4 МГц для RTL-SDR).

**Связь с политикой панорамы (§ 4.4):**
- Спектр живёт на вкладке «Спектр», и открытие этой вкладки и есть `HOLD` (§ 4.3.1): показывает текущий канал, панорама заморожена.
- В `SWEEP` спектра не видно, данные `/spectrum` не запрашиваются — SDR занят обзором. «Антенна» тоже `HOLD`: её компактный спектр — тот же поток канала.

**Toolbar** — компактная горизонтальная строка ~28px над FFT:
- `Device` (read-only из текущего тракта) · `Freq` · `Span` · `Gain` · `Doppler` (auto/manual + слайдер ±25 кГц) · `Pipeline` (auto из SatNOGS / override).
- Значения inline-edit / dropdown. Подробная настройка — по click → расширяемая панель (отдельная задача).
- Ручная смена `Freq` в toolbar тоже переводит панораму в `HOLD` (как клик по передатчику).

**FFT spectrum (мгновенный)** — ≤ полоса SDR, накопление `avg×N` (мельче, чем в Панораме), carrier marker, doppler-prediction overlay.

**Шкала частот** — общая ось для FFT и Waterfall в этом блоке.

**Waterfall** — спектрограмма по времени.

**Связь с текущим каналом:** Спектр всегда отображает данные **текущего канала** (шапка блока «Демодулятор», § 4.7). Смена канала (клик в Панораме, § 4.6) → перенастройка Спектра и метрик.

### 4.6. Поведение клика по передатчику в Панораме

Клик по строке списка передатчиков (или по чипу-маркеру на FFT):

1. **Перенастроить активный канал** на эту частоту — минимум сущностей, единственное поведение в MVP. Добавление второго канала (параллельный приём) — Phase 2+, вместе с § 7.2.
2. **Панорама переходит в `HOLD`** (§ 4.4): обзор останавливается, последние данные панорамы замораживаются с возрастом в шапке; Спектр и демодулятор включаются.
3. **Целевой dwell на этой частоте** — непрерывный приём (пока оператор в `HOLD`), без возврата к обзору по таймеру.
4. **Открывается вкладка «Спектр»** (§ 4.3.1) — она и есть `HOLD`; оператор дальше работает с качеством приёма: спектр, результат, колонка тракта.

**Возврат к сканированию:** вкладка «Панорама» → `SWEEP` (§ 4.4): Спектр/демод останавливаются, обзор возобновляется. Если идёт запись IQ — сначала подтверждение.

**Сопровождение — из follow-иконки в списке передатчиков (ревизия 2026-08-14).** У каждого передатчика иконка-переключатель ◎, видимая только когда ротатор в «Авто» (§ 4.3.1). Клик = настроить приёмник на частоту **и** взять КА передатчика на сопровождение (передатчик закреплён за КА). Повторный клик по ведомому — снять. Передатчики одного КА между собой — только смена частоты приёмника, ротатор остаётся на том же КА (ключ toggle — частота, не NORAD). Прежнее «поворотка не перенастраивается при клике» отменено: в «Авто» follow ведёт и приёмник, и ротатор. Кнопки «Сопровождать / Сброс» в Плане сеансов сняты — единственная точка входа в сопровождение теперь список передатчиков.

#### Блок 4 «Результат приёма» (сменный)

Демодулятор выдаёт биты/baseband, а **тип результата** определяется цепочкой обработки после демода (декодер/рендер), которая приходит из pipeline (SatNOGS / локальная БД). Поэтому блок 4 — **сменный «блок результата»**: его вид зависит от типа передатчика, а не жёстко «таблица ТМИ».

**Размещение (ревизия 2026-10-07):** вкладка «Спектр», под водопадом на всю ширину левой части; виды `Таблица | Hex | Диаграмма` (с 2026-10-08 «Диаграмма» — глазковая диаграмма и профиль пролёта рядом по горизонтали). Полная таблица ТМИ, изображение SSTV/APT или текстовый лог.

**Варианты результата:**

| Вариант | Вход (мод./протокол) | Рендер в блоке | Примеры КА | Скоуп |
|---------|----------------------|----------------|------------|-------|
| **Телеметрия (ТМИ)** | FSK/GFSK/BPSK → AX.25 / CCSDS / `.ksy` | Таблица полей | большинство кубсатов | **Ядро (MVP)** |
| **Цифровые данные / файлы** | те же кадры, payload = бинарь | Hex/файл-вывод | научные кубсаты | Ядро |
| **Текст / сообщения** | AFSK 1200 / packet → AX.25 UI | Текстовый лог | ISS APRS, digipeater | Расширение |
| **CW / Морзе** | OOK/CW огибающая → декодер Морзе | Текст (позывной/бикон) | масса кубсатов | Расширение |
| **Голос (аудио)** | FM / SSB (аналог) | Аудио-плеер + запись | ISS voice, SO-50, RS-44 | Расширение |
| **Изображение — SSTV** | FM → SSTV | Канвас (построчно) | ISS SSTV-события | Расширение |
| **Изображение — APT** | FM → APT (аналог) | Канвас | NOAA-15/18/19 | Расширение |
| **Изображение — LRPT** | QPSK → CCSDS | Канвас | Meteor-M | Расширение (ADR-005 §3.4) |

**Вне скоупа:** HRPT и высокоскоростные метеоданные (X-band) — нужен широкополосный SDR и другая антенна; RTL-SDR на VHF/UHF не тянет.

**Незнакомый сигнал:** тип результата заранее неизвестен → определяется вручную в **Лаборатории сигнала** (ADR-007), после чего протокол/рендер сохраняется в pipeline.

**Вариант «Телеметрия» (реализуется первым):**
- **MVP (1 канал):** одна таблица без вкладок — Время | Frame# | Param | Value | CRC

- Строки с `CRC FAIL` — подсвечены красным
- Горизонтальная прокрутка, автоскролл к последней записи
- Лог событий обнаружения (из Панорамы) может маппиться сюда

#### Блок 5 «Az | Pass profile + Rotator | El»

Нижний блок layout. Три колонки, единая высота строки ≈ 328px (Az/El — фиксированный квадрат 300×300). Сетка: `300 | 1fr | 300`.

**Az компас** (300×300 канвас + info) — полярный компас с разметкой N/E/S/W:
- Зелёная стрелка: target (направление на КА)
- Розовая стрелка: actual (реальное положение антенны, если поворотка подключена)
- Подпись в одну строку: `Аз. ант.: 159°    Аз. КА: 162°`
- При отсутствии поворотки: только target, метка `VIRT`

**El угломер** (300×300 канвас + info) — полукруг 0°–90°:
- Зелёная стрелка: target (расчётный угол места КА)
- Розовая стрелка: actual (поворотка)
- Подпись в одну строку: `Уг. ант.: 65°    Уг. КА: 67°`
- При отсутствии поворотки: только target

**Pass profile + Rotator panel** (центральная колонка, вертикальный стек):

*Pass profile graph* (верхняя половина, ~50%) — split-view график пролёта (см. `docs/img/pass-profile-mockup.png`):
- Верхний под-график: кривая Elevation 0°–90° по времени (AOS → TCA → LOS), точка-маркер с текущим значением `60°`
- Нижний под-график: кривая Doppler shift ±3 кГц по тому же временному диапазону, точка-маркер с текущим `−1200 Hz`
- Сквозной зелёный вертикальный маркер NOW проходит через оба под-графика
- В шапке: название КА + NORAD + `T-AOS HH:MM` / `T-LOS HH:MM` (обратный отсчёт)

*Rotator panel* (нижняя половина, ~50%) — управление поворотным устройством:
- Кнопки `[TRACK]` / `[STOP]` + селектор Mode (`AUTO` / `MANUAL` / `PARK`)
- Текущие значения от rotctld большими цифрами: `Az 159°  El 65°`
- Скорость по осям: `Az: 1.2°/с   El: 0.8°/с`
- Поля ручного ввода: `Az [___]  El [___]  [GO TO]`
- Статус rotctld (LED + текст: `connected` / `disconnected`)
- При отсутствии поворотки: все элементы заблокированы, статус `Rotator: not connected (virtual mode)`

**Правая колонка — SkyView** (320×300): азимутальная проекция неба с траекториями КА. Остаётся в `#right-panel-skyview`, **не переносится** в layout Ручного (`MANUAL-LAYOUT-002` reverted). Располагается под Планом сеансов.

### 4.8. Каналы приёма

Несколько параллельных декодеров на одной полосе SDR. Каждый **канал** — независимая точка настройки и декодирования внутри полосы приёмника:

| Параметр | На канал |
|----------|----------|
| Частота (offset от центра SDR) | Да |
| Pipeline / decoder | Да |
| Doppler correction | Да (свой КА → свой shift) |
| Demod metrics (SNR, BER, Lock) | Да |
| Eye/Constellation | Только **активный** канал |
| Спектр (FFT + waterfall) | Только **активный** канал |
| Телеметрия | По **вкладкам каналов** |

Управление **текущим каналом** — через шапку блока «Демодулятор» (§ 4.7) и Toolbar Спектра. **Текущий канал** определяет данные в Спектре, Eye/Constellation и метриках. Телеметрия в MVP — одна таблица; вкладки каналов — Phase 2+.

> **Термин в коде:** сущность может называться `VFO` (Virtual Frequency Oscillator — заимствование из SatDump / sdr-server). **В UI оператор видит только «канал» / «каналы приёма».**

## 6. Переключение режимов

### 6.1. UI-переключатель

Сегментированный переключатель в app-header: `Авто` / `Ручной` / `Анализ` (`aria-pressed`, как в записи 2026-05-31). Рядом — селектор радиотракта и `⚙ Настройки`.

При `station_type = basic` доступен только сегмент `Анализ`; `Авто` и `Ручной` заблокированы с пояснением «нет радиотрактов» (§ 2.1).

### 6.2. Автопереходы

**Нет.** Только ручной toggle. Авто-tune при переходе Авто→Ручной не делается — оператор настраивает Спектр через Toolbar или клик в Панораме (§ 4.6).

«Сопровождать» в Авто (если тракт с повороткой) переводит **только** в Ручной режим без передачи частоты — последний **активный канал** остаётся без изменений.

### 6.3. Persist

- `localStorage['ux.mainMode']` — `'overview'`, `'manual'` или `'analysis'` (восстановление после F5)
- `localStorage['ux.radioPath']` — последний выбранный радиотракт

### 6.4. CSS-классы

На `<body>` устанавливается класс текущего режима для CSS-правил видимости:
- `mode-overview`
- `mode-manual`
- `mode-analysis`

(Класс `mode-simulation` удалён вместе с режимом.)

### 6.5. ModeManager (JavaScript)

```javascript
class ModeManager {
    setMode(mode)              // 'overview' | 'manual' | 'analysis'
    getMode()
    setRadioPath(pathId)
    getRadioPath()
    hasRotator()               // текущий тракт имеет поворотку?
    onModeChange(callback)
    onRadioPathChange(callback)
}
```

## 7. Связь режимов с радиотрактами

### 7.1. Что меняется при смене радиотракта

| Компонент | Авто (Обзор) | Ручной |
|-----------|--------------|--------|
| Источник IQ-данных | SDR выбранного тракта | SDR выбранного тракта |
| Частотные диапазоны | Span из плана сеансов (§ 2.4); `antenna.freq_range_mhz` — опциональный фильтр | Те же span (для Панорамы) + полоса SDR (для Спектра) |
| Параметры приёмника | Из `receiver.defaults` | Из `receiver.defaults` (на старте) + ручная настройка через Toolbar Спектра и шапку «Текущий канал» в Демодуляторе |
| Az/El графики | Не показываются | Virtual (нет поворотки) или Real (с rotctld) |
| Кнопка «Сопровождать» в Плане сеансов | Доступна если `rotator != null` | Не нужна (пользователь и так в Ручном) |
| Стратегия сканирования | `HopAndDwellStrategy` по списку передатчиков КА в зоне видимости (§ 2.4) | `HopAndDwellStrategy` по span плана сеансов (Панорама) + точечная настройка на **канал** (Спектр) |

### 7.2. Одновременная работа трактов (будущее)

В MVP — один активный тракт. В будущем:
- Обзорный тракт сканирует в фоне (история `tx_cycle` продолжает накапливаться)
- Сопровождающий тракт работает по одному КА в Ручном (Спектр + демодуляция)
- UI показывает данные обоих (split view или overlay)

## 8. Источник списка передатчиков

«Известные передатчики» — это объединённый список несущих, который используется:
- в **Авто** для строк таблицы «Передатчики» и для подсветки чипов в плане сеансов;
- в **Ручном** для чипов-маркеров на FFT и строк списка передатчиков под Панорамой.

### 8.1. Три источника

| Источник | Содержимое | Метод |
|---|---|---|
| **SatNOGS Transmitters API** | https://db.satnogs.org/api/transmitters/ — частота, модуляция, baud rate, статус (active/inactive), привязка к КА (NORAD) | REST, кэш TTL 24h (как `SatNOGS` в `techContext.md`) |
| **Локальная БД** (`data/satellite-scout.db`) | Пользовательские оверрайды + записи для КА без поддержки в SatNOGS + именованные «бывшие unknown»-несущие | SQLite, см. задачу `TX-DB-001` |
| **Энергетически детектированные `unknown`-несущие** | Несущие, найденные детектором `DEMOD-004` вне известных каналов | Детектор (`internal/sdr/detector.go`) → SSE `unknown_carrier` |

### 8.2. Объединение

В UI всегда показывается объединённый список: SatNOGS (база) + локальная БД (оверрайды поверх SatNOGS + свои записи) + текущие активные `unknown`-несущие. Источник помечается значком/тегом в строке (например иконкой: 🛰 SatNOGS / 💾 локальная БД / ❓ unknown).

### 8.3. Именование `unknown`-несущей

Оператор может присвоить детектированной `unknown`-несущей имя/привязку через UI (forms в Ручном). После сохранения запись попадает в локальную БД (`TX-DB-001`) и в дальнейшем отображается как обычный «известный» передатчик.

Подробности схемы локальной БД, миграций, REST-эндпоинтов — в задаче `TX-DB-001` (создаётся в `tasks.md` отдельно).

## 9. Что отклонено

| Решение | Причина отказа |
|---------|----------------|
| Каскадная архитектура (Каскад 1 QFH + Каскад 2 direction) | Не масштабируется на произвольные конфигурации станций |
| 4 режима (Обзор / Ручной / Технологический / Имитация) | Технологический поглощён Ручным — разницы нет |
| Имитация как отдельный режим | Имитатор реализован как радиотракт в `station.json`; не требует отдельного UI-режима |
| Heat-grid эфира в Ручном | Дублирует Панораму; в Ручном живая индикация по передатчикам, а история циклов TX×время — в Авто |
| Авто-tune при переходе Авто→Ручной | Оператор контролирует настройку Спектра/канала вручную; авто-tune ломает «Авто = пассивный мониторинг» |
| Аудио и разворот результата демодуляции в Авто | Один приёмник в hop-and-dwell даёт только фрагменты по длительности `dwell` — прерывистое аудио вводит в заблуждение. В Авто — тип данных и краткий итог (§ 3.7) |
| Непрерывный sweep по `antenna.freq_range_mhz` как основа Панорамы | Диапазон антенны может быть неизвестен оператору; span вокруг частот плана сеансов дешевле (1–2 против 10) и без пустых участков на оси (§ 2.4). Широкий обзор остался опцией по кнопке |
| Жёсткая привязка типа антенны к UI-зоне | Ограничивает операторов с нестандартными конфигурациями |
| HTMX для динамики режимов | SSE + vanilla JS достаточно, HTMX не используется для обмена данными |

**Что берём:**
- Demodulator status: Lock LED, SNR, BER, freq offset, AFC

- Multi-viewport (overkill для web)
- Pipeline editor (у нас предопределённые decoder configs)

## 12. Открытые вопросы (Phase 2+)

1. **UI-редактор схемы станции** — визуальная схема (референс: «Программа управления СП ТМИ»). Для MVP достаточно JSON.
2. **Одновременная работа нескольких трактов** — split view или overlay. MVP: один активный тракт.
3. **Attribution unknown-несущей к КА** (Doppler matching) — автоматическая привязка обнаруженного сигнала к спутнику по Doppler shift; пока — ручное именование (§ 8.3). Пересекается с ADR-007 § 14 п. 3.
4. **Экспорт телеметрии** — CSV/JSON export таблицы принятых пакетов.
5. **Персистентность журнала событий** — связано с ADR-003 § 8 (варианты персистентности).
6. **Сортировка списка передатчиков в Панораме (§ 4.4)** — зафиксировано: по частоте; активные сверху, молчащие снизу внутри диапазона. Пользовательская группировка по КА — опционально Phase 2+.
7. **Коэффициенты `a`, `b` в `w_hist`** (§ 2.4) — стартовые `0.5 / 0.5`, числа уточнить на имитаторе (SDR-005).
8. **Автовывод рабочего диапазона антенны** по статистике приёма (ловим на 145, глухо на 435) с предложением сохранить в config — почти бесплатно поверх `w_hist`, но спекулятивно для MVP.

> Закрыты: **запись baseband** — стала ядром режима Анализ (ADR-007, `SIGLAB-001`); **поведение клика по передатчику** (§ 4.6).
